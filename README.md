# CS-230_OP_Platforms Journal Reflection

Briefly summarize The Gaming Room client and their software requirements. Who was the client? What type of software did they want you to design?

Our client, The Gaming Room client asked us to streamline their game Win it or Lose it. It was only available as an Android app. Their requirement was for me to design their gaming software to run in a web based browser on multiple platforms.

What did you do particularly well in developing this documentation?
I think I did particularly well in developing the evaluation section comparing the pros and cons of each server, costs involved, and explaining the requirements to ensure the game has cross-platform compatibility.

What about the process of working through a design document did you find helpful when developing the code?
I found the UML Diagram very helping for developing the code because it showed how each file inherits from each other. It was also helpful in ensuring that the clients requirements were met for : 

•	The game having the ability to have one or more teams involved

•	Each of the teams having multiple players assigned to it.

•	Game and team names uniqueness to allow users to check whether a name is in use when choosing a team name

•	Only one instance of the game can exist in memory at any given time.


If you could choose one part of your work on these documents to revise, what would you pick? How would you improve it?

If I could choose one part of my work on this document to revised it would be going into greater detail in the recommendation section. I could have elaborated further on the memory management section. 


How did you interpret the user’s needs and implement them into your software design? Why is it so important to consider the user’s needs when designing?

I interpreted the user's needs by thoroughly reviewing and considering the requirements of the software design. It's important to consider the user's needs in the design process because you want to ensure a unique experience for each user. 

How did you approach designing software? What techniques or strategies would you use in the future to analyze and design a similar software application?

When designing software it's important to follow a process of steps to be successful. I approached the design with the mindset of not only as a developer/designer but also as an end user and what I would like to see as the end user of a game. I considered which visually pleasing aspects and features that make for a fun and unique gameplay experience. I thought about my personal experiences when playing games, and the aspects of the game I enjoy that I could integrate into the software. In the future, if I were to design gaming software I would follow the same process I did with this project using a design document and UML diagram to carefully map out the entire process.
